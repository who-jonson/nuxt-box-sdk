Proxy mode is a security feature that ensures Box access tokens never reach the browser. When it is active, your Nitro server intercepts every Box API request, injects a fresh access token, and forwards the request to Box on behalf of the client.

## Why proxy mode exists

When a Vue component or composable makes a Box API call, the request must carry an access token. Without proxy mode, that token must travel to the browser — exposing it to developer tools, network inspection, and any cross-site scripting vulnerability in your app.

Proxy mode eliminates this risk. The browser sends requests to your own server (`/_box/proxy/api`), your server attaches the token it holds server-side, and forwards the request to `https://api.box.com`. The browser never sees the token.

::tip
Proxy mode is enabled by default. You do not need to configure anything to benefit from it.
::

## How it works

The module registers a Nitro middleware that intercepts requests to two paths:

| Proxy path | Forwards to |
|------------|-------------|
| `/_box/proxy/api/*` | `https://api.box.com/*` |
| `/_box/proxy/upload/*` | `https://upload.box.com/api/*` |

When the middleware receives a request, it:

1. Reads the request path and strips the proxy prefix
2. Fetches a valid access token using the configured auth strategy
3. Injects the token into the `Authorization` header
4. Forwards the request to Box using [`httpxy`](https://github.com/unjs/httpxy) (a Nitro-compatible HTTP proxy)
5. Streams the Box response back to the original caller

Client composables (`useBoxFilesManager()`, `useBoxClient()`, etc.) detect the proxy configuration automatically and use `/_box/proxy/api` as their base URL instead of `https://api.box.com` directly.

## Request flow

The following diagram shows the complete flow for a client-side Box API call when proxy mode is active.

```
Browser                 Nitro Server              Box API
  │                          │                        │
  │  GET /_box/proxy/api/    │                        │
  │  files/12345             │                        │
  │ ──────────────────────►  │                        │
  │                          │  fetch access token    │
  │                          │  (from tokenStorage)   │
  │                          │                        │
  │                          │  GET /2.0/files/12345  │
  │                          │  Authorization: Bearer │
  │                          │ ──────────────────────►│
  │                          │                        │
  │                          │       200 OK + body    │
  │                          │ ◄──────────────────────│
  │       200 OK + body      │                        │
  │ ◄──────────────────────  │                        │
  │                          │                        │
```

At no point does the access token appear in a request leaving the browser.

## Configure proxy mode

Proxy mode is on by default with the path `/_box/proxy`. You can change the base path or disable it entirely.

### Change the proxy path

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-box-sdk'],
  box: {
    proxy: '/_api/box',
  },
})
```

Client composables pick up the new path automatically — no additional changes are needed.

### Disable proxy mode

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-box-sdk'],
  box: {
    proxy: false,
  },
})
```

::warning
When you disable proxy mode, client composables call Box API directly from the browser. Access tokens will be visible to the client. Only disable proxy mode if your use case explicitly requires it and you understand the security implications.
::

## Nitro hooks

The module exposes three Nitro hooks for server-side customization. Register them in a Nitro plugin inside `server/plugins/`.

### `box:login:before`

Fires before the OAuth login redirect. Use it to validate the request, add state parameters, or log the event.

```ts [server/plugins/box.ts]
export default defineNitroPlugin((nitro) => {
  nitro.hooks.hook('box:login:before', ({ event, options }) => {
    // Attach a CSRF state token before redirecting
    options.state = generateCsrfToken(event)
  })
})
```

### `box:login:success`

Fires after a successful OAuth token exchange. Use it to store user information, trigger post-login logic, or emit analytics events.

```ts [server/plugins/box.ts]
export default defineNitroPlugin((nitro) => {
  nitro.hooks.hook('box:login:success', ({ event, response }) => {
    // Emit analytics, store user info, etc. — response.accessToken is available here
  })
})
```

### `box:token:storageKey`

Fires when the module constructs the unstorage key for a token. Use it to namespace keys per user or per tenant.

```ts [server/plugins/box.ts]
export default defineNitroPlugin((nitro) => {
  nitro.hooks.hook('box:token:storageKey', ({ auth, key }) => {
    // Prefix the key with a tenant ID for multi-tenant apps
    key.value = `tenant:${getTenantId()}:${key.value}`
  })
})
```

## SSR and proxy mode together

Proxy mode works alongside SSR. During server-side rendering, the Nuxt server executes composable calls directly (without going through the proxy middleware) because the server already has access to auth. The proxy middleware only applies to requests that originate from the browser after hydration.

This means:

- **During SSR**: manager composables call Box directly via server-side auth
- **After hydration**: manager composables route through `/_box/proxy/api`

No configuration change is needed to support this behavior — the module handles the distinction automatically based on whether `import.meta.server` is `true`.

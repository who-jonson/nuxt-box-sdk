The module accepts all options under the `box` key in `nuxt.config.ts`. The following table describes every top-level option.

## Module options reference

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `developer` | `{ token: string }` | — | Developer token config. Active in development mode only. |
| `ccg` | `CcgConfig` | — | Client Credentials Grant auth config. |
| `jwt` | `JwtConfig` | — | JWT auth config for enterprise apps. |
| `oauth` | `OAuthConfig` | — | OAuth 2.0 config for end-user auth. |
| `managers.include` | `string[]` | all managers | List of manager names to include in the build. |
| `managers.exclude` | `string[]` | `[]` | List of manager names to exclude from the build. Ignored when `include` is set. |
| `proxy` | `string \| false` | `'/_box/proxy'` | Base path for the proxy middleware. Set to `false` to disable. |
| `ssr` | `boolean` | `true` | Enables SSR support and server-side auth utilities. |
| `tokenStorage` | `string` | `'cache'` | Nitro unstorage mount name for server-side token persistence. |
| `mode` | `'auto' \| 'client' \| 'server'` | `'auto'` | Controls which parts of the module are registered. |

## Complete configuration example

The following example shows every available option with comments explaining each one.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-box-sdk'],

  box: {
    // --- Auth strategies (configure one for production) ---

    // Developer token: local development only, expires after 60 minutes
    developer: {
      token: process.env.BOX_DEVELOPER_TOKEN,
    },

    // CCG: server-to-server, service account or user auth
    ccg: {
      clientId: process.env.NUXT_BOX_CCG_CLIENT_ID,
      clientSecret: process.env.NUXT_BOX_CCG_CLIENT_SECRET,
      enterpriseId: process.env.NUXT_BOX_CCG_ENTERPRISE_ID,
      // or userId for acting as a specific user:
      // userId: process.env.NUXT_BOX_CCG_USER_ID,
    },

    // JWT: enterprise apps with a Box JWT application
    jwt: {
      clientId: process.env.NUXT_BOX_JWT_CLIENT_ID,
      clientSecret: process.env.NUXT_BOX_JWT_CLIENT_SECRET,
      jwtKeyId: process.env.NUXT_BOX_JWT_KEY_ID,
      privateKey: process.env.NUXT_BOX_JWT_PRIVATE_KEY,
      privateKeyPassphrase: process.env.NUXT_BOX_JWT_PASSPHRASE,
      enterpriseId: process.env.NUXT_BOX_JWT_ENTERPRISE_ID,
    },

    // OAuth: end-user authentication via Box login
    oauth: {
      clientId: process.env.NUXT_BOX_OAUTH_CLIENT_ID,
      clientSecret: process.env.NUXT_BOX_OAUTH_CLIENT_SECRET,
    },

    // --- Tree-shaking: include only what you need ---
    managers: {
      // include specific managers (mutually exclusive with exclude)
      include: ['files', 'folders', 'search', 'shared-links'],
      // or exclude managers you don't need:
      // exclude: ['webhooks', 'retention-policies', 'legal-hold-policies'],
    },

    // --- Proxy mode ---
    // Set to false to disable, or a custom path string to change the base URL
    proxy: '/_box/proxy',

    // --- SSR ---
    // Set to false if you only need client-side Box access
    ssr: true,

    // --- Token storage ---
    // Nitro unstorage mount name (default: 'cache')
    // Use 'redis' or another mount for persistent storage in production
    tokenStorage: 'cache',

    // --- Module mode ---
    // 'auto'   — registers both client composables and server utilities (default)
    // 'client' — registers client composables only, skips server registration
    // 'server' — registers server utilities only, skips client auto-imports
    mode: 'auto',
  },
})
```

## Tree-shaking with `managers`

The `managers` option controls which Box API managers are generated and bundled.

Use `include` to explicitly list the managers your app uses. Only those managers will be bundled, and only their composables (`useBoxFilesManager`, `useBoxFoldersManager`, etc.) will be auto-imported.

```ts [nuxt.config.ts]
box: {
  managers: {
    include: ['files', 'folders', 'search'],
  },
},
```

Use `exclude` when you want most managers but need to drop a few.

```ts [nuxt.config.ts]
box: {
  managers: {
    exclude: ['webhooks', 'retention-policies', 'legal-hold-policies'],
  },
},
```

::note
`include` takes precedence over `exclude`. If you set both, `exclude` is ignored.
::

## Module mode

The `mode` option controls which parts of the module are active.

| Mode | Client composables | Server utilities |
|------|-------------------|-----------------|
| `'auto'` (default) | Yes | Yes |
| `'client'` | Yes | No |
| `'server'` | No | Yes |

Use `'server'` when you only need server-side Box access (for example, a purely server-rendered app that never runs Box calls in the browser).

## Token storage

Server-side token persistence uses [Nitro's unstorage](https://nitro.unjs.io/guide/storage). The `tokenStorage` option accepts the name of any configured unstorage mount. The default is `'cache'`, which Nitro provides out of the box.

To persist tokens across server restarts (for example with a Redis store), configure the unstorage driver in `nuxt.config.ts` and point `tokenStorage` at it.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  nitro: {
    storage: {
      redis: {
        driver: 'redis',
        url: process.env.REDIS_URL,
      },
    },
  },
  box: {
    tokenStorage: 'redis',
  },
})
```

::tip
Each auth strategy can override the global `tokenStorage` with its own value by setting `tokenStorage` inside the auth config object.
::

## Environment variables

All sensitive auth values should come from environment variables. The following prefixes are supported for automatic runtime config injection:

| Auth type | Prefix |
|-----------|--------|
| Developer | `BOX_DEVELOPER_TOKEN` or `NUXT_PUBLIC_BOX_DEVELOPER_TOKEN` |
| CCG | `NUXT_BOX_CCG_*` |
| JWT | `NUXT_BOX_JWT_*` |
| OAuth | `NUXT_BOX_OAUTH_*` |

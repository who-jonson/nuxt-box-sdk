`nuxt-box-sdk` supports four authentication strategies. You configure one per application, though you can define multiple strategies in `nuxt.config.ts` and switch between them at runtime using `useBoxAuthConfig()`.

::note
The `dev` strategy is only active when `import.meta.dev` is `true`. In production, the module falls back to whichever of `ccg`, `jwt`, or `oauth` is configured.
::

## Developer token

### When to use

Use the developer token strategy during local development only. Tokens expire after 60 minutes and must be regenerated manually from the Box Developer Console. This strategy is never active in production.

### Configure

Generate a developer token from your app's **Configuration** page in the [Box Developer Console](https://app.box.com/developers/console).

```bash [.env]
BOX_DEVELOPER_TOKEN=your_developer_token_here
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-box-sdk'],
  box: {
    developer: {
      token: process.env.BOX_DEVELOPER_TOKEN,
    },
  },
})
```

### Use in a component

```vue [pages/index.vue]
<script setup lang="ts">
const filesManager = useBoxFilesManager()

const { data: file } = await filesManager
  .withAsyncData()
  .getFileById('12345')
</script>
```

## Client Credentials Grant (CCG)

### When to use

CCG is the recommended strategy for server-to-server integrations where your application acts as a service account or on behalf of a specific managed user. It does not require user interaction and works well for automated workflows, background jobs, and admin tools.

### Required env vars

| Variable | Description |
|----------|-------------|
| `NUXT_BOX_CCG_CLIENT_ID` | Your Box app's client ID |
| `NUXT_BOX_CCG_CLIENT_SECRET` | Your Box app's client secret |
| `NUXT_BOX_CCG_ENTERPRISE_ID` | Enterprise ID (for service account auth) |
| `NUXT_BOX_CCG_USER_ID` | User ID (alternative to `ENTERPRISE_ID` for user auth) |

### Configure

```bash [.env]
NUXT_BOX_CCG_CLIENT_ID=your_client_id
NUXT_BOX_CCG_CLIENT_SECRET=your_client_secret
NUXT_BOX_CCG_ENTERPRISE_ID=your_enterprise_id
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-box-sdk'],
  box: {
    ccg: {
      clientId: process.env.NUXT_BOX_CCG_CLIENT_ID,
      clientSecret: process.env.NUXT_BOX_CCG_CLIENT_SECRET,
      enterpriseId: process.env.NUXT_BOX_CCG_ENTERPRISE_ID,
    },
  },
})
```

To act as a specific managed user instead of the service account, use `userId` in place of `enterpriseId`:

```ts [nuxt.config.ts]
box: {
  ccg: {
    clientId: process.env.NUXT_BOX_CCG_CLIENT_ID,
    clientSecret: process.env.NUXT_BOX_CCG_CLIENT_SECRET,
    userId: process.env.NUXT_BOX_CCG_USER_ID,
  },
},
```

### Use a CCG client on the server

```ts [server/api/files.ts]
export default defineEventHandler(async () => {
  const client = useBoxCcgClient()
  const items = await client.folders.getFolderItems('0')
  return items
})
```

## JWT

### When to use

Use JWT when your Box application is configured with a JWT auth type in the Developer Console. JWT is common in enterprise deployments that need to impersonate users or act as a service account with a full RSA key pair. It requires your Box admin to approve the application.

### Required env vars

| Variable | Description |
|----------|-------------|
| `NUXT_BOX_JWT_CLIENT_ID` | Your Box app's client ID |
| `NUXT_BOX_JWT_CLIENT_SECRET` | Your Box app's client secret |
| `NUXT_BOX_JWT_KEY_ID` | The ID of the JWT public key |
| `NUXT_BOX_JWT_PRIVATE_KEY` | The RSA private key (PEM format) |
| `NUXT_BOX_JWT_PASSPHRASE` | Passphrase for the private key |
| `NUXT_BOX_JWT_ENTERPRISE_ID` | Your Box enterprise ID |

### Configure

```bash [.env]
NUXT_BOX_JWT_CLIENT_ID=your_client_id
NUXT_BOX_JWT_CLIENT_SECRET=your_client_secret
NUXT_BOX_JWT_KEY_ID=your_key_id
NUXT_BOX_JWT_PRIVATE_KEY="-----BEGIN ENCRYPTED PRIVATE KEY-----\n..."
NUXT_BOX_JWT_PASSPHRASE=your_passphrase
NUXT_BOX_JWT_ENTERPRISE_ID=your_enterprise_id
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-box-sdk'],
  box: {
    jwt: {
      clientId: process.env.NUXT_BOX_JWT_CLIENT_ID,
      clientSecret: process.env.NUXT_BOX_JWT_CLIENT_SECRET,
      jwtKeyId: process.env.NUXT_BOX_JWT_KEY_ID,
      privateKey: process.env.NUXT_BOX_JWT_PRIVATE_KEY,
      privateKeyPassphrase: process.env.NUXT_BOX_JWT_PASSPHRASE,
      enterpriseId: process.env.NUXT_BOX_JWT_ENTERPRISE_ID,
    },
  },
})
```

::tip
Box provides a JSON config file download from the Developer Console that contains all required JWT values. You can load this file and spread its contents into the `jwt` config object.
::

### Use a JWT client on the server

```ts [server/api/admin/users.ts]
export default defineEventHandler(async () => {
  const client = useBoxJwtClient()
  const users = await client.users.getUsers()
  return users
})
```

## OAuth

### When to use

Use OAuth when your application needs end users to authenticate with their own Box accounts. This strategy initiates the standard OAuth 2.0 authorization code flow. Use it for apps where users manage their own Box content.

### Required env vars

| Variable | Description |
|----------|-------------|
| `NUXT_BOX_OAUTH_CLIENT_ID` | Your Box app's client ID |
| `NUXT_BOX_OAUTH_CLIENT_SECRET` | Your Box app's client secret |

### Configure

```bash [.env]
NUXT_BOX_OAUTH_CLIENT_ID=your_client_id
NUXT_BOX_OAUTH_CLIENT_SECRET=your_client_secret
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-box-sdk'],
  box: {
    oauth: {
      clientId: process.env.NUXT_BOX_OAUTH_CLIENT_ID,
      clientSecret: process.env.NUXT_BOX_OAUTH_CLIENT_SECRET,
    },
  },
})
```

The module automatically registers two server routes for the OAuth flow:

- `GET /_box/authenticate` — redirects the user to the Box login page
- `GET /_box/authenticate/callback` — receives the authorization code and exchanges it for tokens

### Initiate the login flow

Redirect the user to `/_box/authenticate` to start the OAuth flow. After the user authorizes your app, Box redirects them to `/_box/authenticate/callback`, and the module stores the tokens using the configured `tokenStorage`.

```vue [pages/login.vue]
<script setup lang="ts">
function loginWithBox() {
  navigateTo('/_box/authenticate', { external: true })
}
</script>

<template>
  <button @click="loginWithBox">
    Connect with Box
  </button>
</template>
```

### Use the OAuth client after login

Once the user is authenticated, use `useBoxOAuth()` to get the auth object and `useBoxClient()` to get a client instance operating as that user.

```ts [server/api/me.ts]
export default defineEventHandler(async (event) => {
  const client = await useBoxOAuthClient(event)
  const currentUser = await client.users.getUserMe()
  return currentUser
})
```

## Access auth config at runtime

Use `useBoxAuthConfig()` to read the currently active auth configuration on the client, or `useBoxAuth()` to get the underlying auth object.

```ts
const authConfig = useBoxAuthConfig()
console.log(authConfig.type) // 'ccg' | 'jwt' | 'oauth' | 'dev'
```

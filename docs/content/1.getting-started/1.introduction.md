`nuxt-box-sdk` is a Nuxt module that integrates [box-node-sdk](https://github.com/box/box-node-sdk) into your Nuxt application. It provides auto-imported composables, server-side auth utilities, a secure proxy mode, and build-time tree-shaking — all configured through `nuxt.config.ts`.

## Why use nuxt-box-sdk instead of box-node-sdk directly?

You can install `box-node-sdk` in a Nuxt project and use it manually, but you immediately face several friction points. `nuxt-box-sdk` solves each of them.

### Tree-shaking

`box-node-sdk` ships more than 50 API managers — files, folders, search, webhooks, retention policies, and many more. Importing the full SDK bundles all of them, even if your app only needs two or three.

`nuxt-box-sdk` generates the `BoxClient` class and all composables **at build time**, filtered by `managers.include` or `managers.exclude`. Setting `managers.include: ['files', 'folders']` means only those two managers ever reach your bundle.

### SSR integration

Using the raw SDK in a Nuxt app requires manually handling the server/client boundary. You must decide where auth runs, how tokens are stored, and how to avoid running server-only code in the browser.

`nuxt-box-sdk` handles this automatically. Server utilities live in `server/`, client composables handle the browser context, and the shared auth layer bridges both sides correctly during SSR and hydration.

### Proxy mode security

When Box API calls originate from the browser, access tokens must travel to the client. This exposes them to browser developer tools, network inspection, and XSS attacks.

`nuxt-box-sdk`'s proxy mode routes all Box API calls through your Nitro server. The browser never sees a token — it sends a request to `/_box/proxy/api`, your server injects the token, and forwards the request to Box. Credentials stay server-side by design.

### Auth management

Bootstrapping CCG, JWT, or OAuth auth from scratch in a Nuxt app means writing integration code across `nuxt.config.ts`, server routes, environment variables, and runtime config. `nuxt-box-sdk` handles all of that with a single config key per auth type.

## Core concepts

### Managers

A Box manager is a class that wraps a section of the Box API — `FilesManager`, `FoldersManager`, `SearchManager`, and so on. `nuxt-box-sdk` generates a composable for each included manager: `useBoxFilesManager()`, `useBoxFoldersManager()`, etc.

Each composable returns a manager instance extended with `withAsyncData()`, `useLazyAsyncData()`, and network session helpers.

### Auth strategies

The module supports four authentication types. You configure one (or more) in `nuxt.config.ts` or via environment variables. See the [Authentication guide](/guide/authentication) for details on each strategy.

| Strategy | Config key | Best for |
|----------|------------|----------|
| `dev` | `developer.token` | Local development only |
| `ccg` | `ccg` | Server-to-server (service accounts) |
| `jwt` | `jwt` | Enterprise apps with a Box JWT app |
| `oauth` | `oauth` | End-user authentication |

### Proxy mode

When `proxy` is set (it defaults to `'/_box/proxy'`), the module registers a Nitro middleware that intercepts requests to `/_box/proxy/api` and `/_box/proxy/upload`, fetches a server-side access token, and forwards the request to Box. Client composables automatically route through the proxy when it is configured.

## Prerequisites

Before you start, make sure you have the following:

- **Nuxt 4** or later
- **Node.js 20** or later
- **pnpm**, npm, or yarn
- A [Box developer account](https://developer.box.com/) with an application created in the [Box Developer Console](https://app.box.com/developers/console)

::tip
If you are new to Box development, the [Box Developer Quickstart](https://developer.box.com/guides/getting-started/) walks you through creating your first app and choosing an auth type.
::
